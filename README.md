# Polymorfe-obfuscation core

>[!NOTE] Полиморфная обфускация одной функции в C-исходнике по данным инспектора ELF.
Инспектор разбирает скомпилированный бинарник и находит функции-кандидаты,
обфускатор переписывает тело выбранной функции эквивалентными преобразованиями.
Каждый запуск даёт НОВЫЙ вариант кода с тем же поведением: все решения
принимает ГПСЧ SplitMix64, посеянный зерном (`-s`). Ключ `-s 42` даёт
побайтово одинаковый результат при повторе (воспроизводимость), без `-s`
зерно берётся из системных часов — варианты непохожи. Эквивалентность
доказывается прогоном: вывод оригинала и обфусцированной версии обязан
совпасть.

## Использование с примерами

### Сборка

```bash
cargo build --release
# бинарники: target/release/obfuscator-core, target/release/elf-inspector,
#            target/release/obfuscator
```

### Полный конвейер: obfuscator-core -obf

Компилирует исходник, инспектирует ELF, выбирает функцию (по умолчанию —
крупнейшая помимо `main`/`_start`), обфусцирует её, компилирует обе версии
и сверяет вывод.

```bash
./target/release/obfuscator-core -obf examples/demo.c            # новый вариант при каждом запуске
./target/release/obfuscator-core -obf examples/demo.c -s 42      # воспроизводимый вариант
./target/release/obfuscator-core -obf examples/demo.c -s 0xfeed  # зерно в hex
./target/release/obfuscator-core -obf examples/demo.c -f gcd     # выбрать функцию самому
```

Пример вывода `obfuscator-core -obf examples/demo.c -s 42` (подрезан):

### Инспектор: obfuscator-core inspect / elf-inspector

```bash
./target/release/obfuscator-core inspect examples/demo.c      # полный отчёт по ELF
./target/release/elf-inspector <программа> --json info.json   # кандидаты в JSON
```

`inspect` печатает ELF-заголовок (магию, класс, точку входа), программные
заголовки, интерпретатор, зависимости `DT_NEEDED`, секции и таблицу
функций. `elf-inspector --json` сохраняет кандидатов в формате
`elf-inspector-candidates-v1` — имя, адрес, размер, смещение в файле,
секция; этот JSON — вход для автономного обфускатора.

### Автономный обфускатор: obfuscator

Берёт C-файл и JSON кандидатов от `elf-inspector`; не компилирует и не
проверяет — только переписывает исходник.

```bash
./target/release/obfuscator examples/demo.c info.json -s 42 -o out.c
```

## Краткое описание модулей

- **pipeline** (`src/pipeline.rs`) — полный конвейер из шести шагов:
  компиляция оригинала, инспекция ELF и выбор функции, обфускация,
  компиляция обфусцированной версии, прогон обеих версий со сравнением
  вывода, повторная инспекция (как выросла функция). Здесь же
  фиксируется зерно и итоговый вердикт эквивалентности.
- **obfsource** (`src/obfsource.rs`) — полиморфный движок обфускации
  тела функции: SplitMix64 с зерном, переименование локальных
  переменных (5 случайных стилей имён), разложение десятичных литералов
  на выражения одной из 5 форм с вложенностью до 3 слоёв, мёртвые блоки
  (volatile-флаг и непрозрачный предикат «p*(p+1) всегда чётно»),
  безвредные блоки под всегда истинным предикатом, мусорные комментарии
  и случайный порядок вставок. Токенизатор защищает строки, символы,
  комментарии и препроцессорные строки.
- **obfuscator** (`src/bin/obfuscator.rs`) — автономный обфускатор:
  принимает C-файл и JSON кандидатов от `elf-inspector`, выбирает
  функцию ключом `-f`, обфусцирует с зерном `-s` и записывает новый
  исходник. Без компиляции и проверки эквивалентности — быстрый режим
  для ручной работы.
- **tests** (`tests/`) — комплект тестов: `config_tests.rs` (публичный
  API: воспроизводимость по seed, различие вариантов, сохранность
  препроцессорных строк и строковых литералов, полнота переименований)
  и `pipeline_tests.rs` (стресс-тест 30 прогонов эквивалентности через
  gcc). Внутренности движка покрыты юнит-тестами в `src/obfsource.rs`.

## Пример обфусц кода

*Обычный код👇*
```C
/* Демо-программа для obfuscator-core.
 *
 * Запуск полного конвейера:
 *   obfuscator-core -obf demo.c
 * Инспектор найдёт в скомпилированном ELF функции sum_to, collatz_len,
 * gcd и main; обфускатор перепишет одну из них (по умолчанию —
 * collatz_len, самую крупную) в новом файле demo_obf.c, после чего
 * обе версии компилируются и запускаются — вывод обязан совпасть:
 *   sum_to(10)=55
 *   collatz_len(27)=111
 *   gcd(462,1071)=21
 */
#include <stdio.h>

static long sum_to(long n) {
    long s = 0;
    for (long i = 1; i <= n; i++) {
        s = s + i;
    }
    return s;
}

/* Длина траектории Коллатца: сколько шагов нужно, чтобы n дошло до 1. */
static long collatz_len(long n) {
    long steps = 0;
    while (n != 1) {
        if (n % 2 == 0) {
            n = n / 2;
        } else {
            n = 3 * n + 1;
        }
        steps = steps + 1;
    }
    return steps;
}

/* НОД двух чисел алгоритмом Евклида. */
static int gcd(int a, int b) {
    while (b != 0) {
        int t = a % b;
        a = b;
        b = t;
    }
    return a;
}

int main(void) {
    printf("sum_to(10)=%ld\n", sum_to(10));
    printf("collatz_len(27)=%ld\n", collatz_len(27));
    printf("gcd(462,1071)=%d\n", gcd(462, 1071));
    return 0;
}

```

    long junk_7326 = ((1442 << 3) + 3);
    if (((junk_7326 * (junk_7326 + 1)) % 2) != 0) {

        unused_34b6 ^= (298 + 3460);
        (void)unused_34b6;

    /* мёртвая ветвь: p*(p+1) всегда чётно, условие ложно */
    long obf_gate_3def = (25209 ^ 5132);

        dead_064c ^= (1395 + 2222);
        (void)dead_064c;

    long wv72 = (1236 - 1236);

        if (var_261 % 2 == ((5514 + 4587) ^ (5514 + 4587))) {
            var_261 = var_261 / (4 * 5 - 18);

            var_261 = 3 * var_261 + ((15303 ^ 15309) * (5 + 7) - (12 * 3 + 83));

#### Заметки

Обфускация должна мутировать код так, чтобы код противоречил "соглашение об именновании":

- имена переменных противоречат **snake_case**
- имена переменных должны быть длинными либо слишком короткими, исключая четкие описания
- имена содержащие цифры должны запутать или не иметь смысла
- простые счётчики типа(i,j)

Обфускация должна мутировать код так, чтобы запутать логику работы кода:

- Добавлять лишние циклы(функции), удлинять циклы(функции), диверсифицировать функцию на несколько и т.д.
- уменьшать или увеличивать вычисления
- константы, строки могут объединяться в один массив и использоваться по запутанным индексам

Дополнительно:

- антиотладчик
- удаление комментариев-пояснений(минификация)

### Обфускация готовых ELF-файлов (obfelf.rs)

Тип входного файла определяется автоматически по ELF-магии: `obfuscator-core -obf /bin/ls`
работает без исходника. Инспектор читает ELF и передаёт обфускатору карту функций
(кандидаты из .symtab/.dynsym + диапазоны FDE из unwind-таблицы .eh_frame — они есть даже
у stripped-бинарников); обфускатор меняет только то, что не участвует в работе программы:

- **code caves** — паддинг (серии 00/90/CC от 6 байт) в исполняемых секциях строго между
  двумя соседними границами функций с зазором ≤ 32 байт (там может быть только выравнивание);
- **.comment** — подпись компилятора заменяется случайной (антифингерпринт);
- **межсекционные гэпы** файла — выравнивание, не покрытое секциями и таблицами;
- **junk-секция** — безымянная секция в конце файла (загрузчик её не читает).

Паддинг e_ident[EI_PAD] намеренно не трогается: glibc (ld.so --verify, а значит и ldd)
требует нулевой паддинг заголовка.

Зачем такая строгость: серия нулей может оказаться частью инструкции (disp32+imm32 дают
до 8 нулей подряд внутри `mov $0, 0xc8(%r12)`), а nop-сани — исполняемым кодом; правило
«между соседними FDE ≤ 32 байт» проверено запуском на /bin/ls, /bin/cat, /bin/bash,
gcc и curl. Все замены, кроме junk-секции, сохраняют длину файла; результат записывается
в `.obf-build/` (или в текущий каталог, если рядом нельзя) и сразу запускается рядом с
оригиналом — вывод обязан совпасть. Ключи `-s` (зерно) и `-f` работают так же, как в
C-конвейере; `obfuscator-core inspect /bin/ls` печатает отчёт инспектора без компиляции.
